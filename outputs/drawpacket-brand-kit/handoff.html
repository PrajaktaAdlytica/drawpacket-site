Implementation handoff

A practical handoff for implementing DrawPacket’s website from the approved identity and the page-motion atlas.

This package is a brand kit and interactive visual prototype. It does not deploy the website or implement payment workflows. Use the interactive kit to inspect the actual assets and behavior.

Open index.html for a simple local preview. For consistent SVG-sprite behavior and clipboard access, serve the extracted folder locally:

python3 -m http.server 4173 --directory /path/to/drawpacket-brand-kit

Then visit http://localhost:4173. No build system or hosted service is required. The kit loads no remote fonts, analytics, or application API.

Brand and layout contract

  • Primary palette: chalk #F5F5F1, oxblood #642A37, ink #252225, lilac #DFDBE8. Accent surfaces are mist, sand, sage, blush, and butter.
  • Font hierarchy: Bodoni Moda 500 headlines; DM Sans body/UI; IBM Plex Mono IDs/amounts; Source Serif 4 for editable logo lettering only.
  • 12 / 8 / 4 columns at desktop / tablet / mobile; 48 / 32 / 20 px outer gutters; max 1280 px content, 680 px reading measure.
  • 4 px spacing base; 24 px card padding; 48 px controls; 44 px minimum tap targets; 4 px control radius; 8 px larger panels.
  • Start each section from one clear alignment. Headings and paragraph edges align; numerical columns are right aligned with tabular figures.
  • Background patterns are decorative, low contrast, and excluded from accessible descriptions. Meaningful figures have a concise text equivalent.

The atlas implements simple staged SVG entries to make the compositions reviewable. The manifest’s exact choreography is the production direction, not a claim that every proposed timed substep has already been implemented. No infinite animation, autoplay audio, or MP4 export is included.

Amounts are illustrative current gross amounts, not a complete AIA payment certificate. Prior payments, tax, retainage, and contractual terms are excluded assumptions, so the preview must not imply these values are an executable amount due.

States and motion meaning

The website may animate received → variance identified → evidence hold → reviewer views source → draft packet. Resolution requires an explicit reviewer action with evidence in a later deterministic demo. A decorative animation must not move the record to approved, signed, sent, or paid. Human approval must be a distinct named event.

Conditional and unconditional waiver states remain distinct. A signature alone is not proof of payment. Use counsel-approved state/contract-specific forms; the map and copy are informational illustrations. Keep any recorded GC authorization separate from actual payment execution.

CTA, form and analytics contract

Primary CTA: Explore synthetic demo. Conversion CTA: Request a scoped pilot. Secondary CTA: Inspect source evidence. Do not invent a working login or successful form submission in the brand preview.

Intake fields: business email, role, company, selected offer ID, one-project/cycle scope, named AP owner, data/template access status, optional current tool, explicit purpose-limited consent. Display privacy purpose, deletion route, and no-sensitive-records instruction. No raw financial documents in the form.

Analytics allowlist: landing_view, buyer_qualified, offer_19_selected with selected offer ID, demo_open, evidence_view, override_view, price_view, pilot_request, consent_submit. Store UTM source/campaign, not raw financial records. Only emit consent_submit after real validation and a confirmed backend response. Deduplicate qualified leads; clicks are not purchases.

Validation gate

Go only when a supervised cycle demonstrates fewer true returns without wrongful holds, approved state-specific templates, and a funded project owner. Stop if waiver complexity or incumbent coverage erases incremental value. Track GC-validated avoided returns, review hours, missed material holds, false positives/omissions, subcontractor response burden, and paid pilot commitment. No scorecard value is invented in this kit.

Delivery checks and limits

See the machine-readable validation report for file, arithmetic, and contrast checks. Browser captures record representative desktop and mobile states. These checks are not a production security, legal, accessibility, or performance certification.

Before a website launch: connect real forms, confirm consent/privacy copy, verify real profile URLs, review legal wording, optimize route assets, run device/accessibility QA, check domain/trademark availability, and deploy through the agreed hosting workflow. Those are subsequent website-build tasks.
